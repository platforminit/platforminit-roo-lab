# CH04 — Platform Services GitOps Contract (Traefik, cert-manager, Argo CD)

## Purpose

CH04 turns the CH03 single-node k3s cluster into a GitOps-managed platform:

- Traefik exposes platform services on ports 80/443 through a `LoadBalancer` service (k3s ServiceLB), and a pending LoadBalancer endpoint fails validation.
- cert-manager issues Let's Encrypt certificates with the Cloudflare DNS-01 solver, proven by an opt-in staging issuance smoke check.
- Argo CD is the GitOps control plane: it bootstraps itself once, then owns its own AppProject and ApplicationSet, and deploys every platform service from Git.

## Ownership model

| Concern | Bootstrap (imperative, once) | Steady state (GitOps) |
|---|---|---|
| Traefik exposure | k3s `HelmChartConfig` mounted/installed by CH03 | [`platform/cluster/manifests/traefik/`](../platform/cluster/manifests/traefik:1) synced by Argo CD |
| cert-manager control plane | [`install-cert-manager.sh`](../platform/cluster/addons/cert-manager/install-cert-manager.sh:1) | — |
| Cloudflare API token secret | synced by the bootstrap script from `CF_API_TOKEN` | never stored in Git |
| ClusterIssuers | — | [`clusterissuer-letsencrypt-cloudflare.yaml`](../platform/cluster/addons/cert-manager/clusterissuer-letsencrypt-cloudflare.yaml:1) |
| Staging issuance smoke | operator-run, opt-in: [`ch04-smoke-staging-certificate.sh`](../platform/cluster/validate/ch04-smoke-staging-certificate.sh:1) | — (temporary resources, removed on exit) |
| Argo CD control plane | [`bootstrap-argocd.sh`](../platform/cluster/addons/argocd/bootstrap-argocd.sh:1) | [`application-argocd-self.yaml`](../platform/cluster/manifests/argocd/application-argocd-self.yaml:1) |
| AppProject + ApplicationSet | created by `argocd-self` on first sync | [`platform/cluster/manifests/argocd/`](../platform/cluster/manifests/argocd:1) |
| Platform service Applications | — | generated by the `platform-services` ApplicationSet |

**Rule:** after bootstrap, platform services are deployed by Argo CD. `kubectl apply` is reserved for the one-time control-plane bootstrap (Argo CD itself, cert-manager CRDs), the guarded pre-promotion rehearsal path described below, and break-glass recovery.

## Bootstrap sequence

```bash
# 1. cert-manager control plane + Cloudflare token secret
sudo PLATFORMINIT_ALLOW_LIVE_CERT_MANAGER_INSTALL=true \
  CF_API_TOKEN="$CF_API_TOKEN" \
  bash platform/cluster/addons/cert-manager/install-cert-manager.sh

# 2. Argo CD control plane + self-management application
sudo PLATFORMINIT_ALLOW_LIVE_ARGOCD_BOOTSTRAP=true \
  bash platform/cluster/addons/argocd/bootstrap-argocd.sh
```

Both scripts are idempotent, require an explicit live-install acknowledgement variable, and never print secret values.

`ARGOCD_SYNC_TIMEOUT` (default 300s, validated range 30-1800s) bounds the wait for `argocd-self` to reach
`Synced`. It must be plain base-10 digits and is type/range-checked before the first arithmetic use and the
first cluster call: the wait helpers evaluate it inside Bash arithmetic, so an unvalidated value could
otherwise execute a command in this root-run script.

## Upstream install integrity (bootstrap scripts)

The two bootstrap scripts are the only root-run paths that apply upstream YAML, so the fetched payload
is an integrity boundary, not just a version string:

- **No arbitrary manifest URL.** The manifest URL is built from a fixed HTTPS origin plus the requested
  version and is matched against a strict host/path allowlist before the download starts. It is
  **not operator-overridable**: the origin is a constant in the script, and the URL override input that
  used to exist was removed from the accepted path by the security fix batch.
- **Validated version syntax.** `ARGO_VERSION` / `CM_VERSION` must match `vMAJOR.MINOR.PATCH`, and the
  requested version must have a committed pin. An unpinned version is refused instead of installed
  unverified.
- **Committed SHA-256 pin.** Each script keeps a `*_PINNED_MANIFEST_SHA256` value next to its pinned
  version. The manifest is downloaded to temporary storage, hashed with `sha256sum`, compared with the
  committed value, and only the verified local file is handed to `kubectl apply` (never a URL). A
  mismatch aborts before the first cluster mutation, and the temporary copy is removed on exit.
- **Version and digest stay in Git**, so an upstream change cannot reach the cluster without a reviewed
  change in this repository. The digest is trust-on-first-use for the official release asset, which is
  exactly why refreshing it is a reviewed commit.

Pin refresh (only after reviewing the upstream release notes):

```bash
# 1. Download the release asset and compute its digest.
curl --fail --location --proto '=https' \
  -o /tmp/cert-manager.yaml \
  https://github.com/cert-manager/cert-manager/releases/download/v1.14.5/cert-manager.yaml
sha256sum /tmp/cert-manager.yaml

# 2. Update CM_PINNED_VERSION + CM_PINNED_MANIFEST_SHA256 in
#    addons/cert-manager/install-cert-manager.sh (or the ARGO_* pair in
#    addons/argocd/bootstrap-argocd.sh) in the same commit, then run:
bash platform/cluster/validate/ch04-validate-platform-services-gitops-contract.sh
```

`git`, `curl` and `sha256sum` are host prerequisites for the bootstrap scripts.

## Fresh-cluster bootstrap ordering

`argocd-self` runs in Argo CD's built-in `default` project:

- The `platform-services` AppProject lives inside `platform/cluster/manifests/argocd`, which is exactly the directory `argocd-self` reconciles. Making `argocd-self` depend on that AppProject would be a circular first-boot dependency: Argo CD rejects an Application whose project does not exist yet, so a fresh cluster could never create either object.
- `default` always exists, cannot be deleted, and has no source/destination restriction, so bootstrap never needs an imperative AppProject pre-create. The scoped `platform-services` AppProject (source repositories, namespaces) applies from the second reconcile onward, when `argocd-self` syncs the directory.
- The repository-only validator fails if `argocd-self` is moved back to `platform-services` without an explicit AppProject pre-bootstrap step.

## GitOps source inputs and promotion

The GitOps source is an explicit deployment input, not a hard-coded repository:

| Input | Default | Meaning |
|---|---|---|
| `PLATFORMINIT_GITOPS_REPO_URL` | `https://github.com/platforminit/platforminit-roo-lab.git` | Repository Argo CD fetches |
| `PLATFORMINIT_GITOPS_TARGET_REVISION` | `dev` | Revision Argo CD fetches |
| `PLATFORMINIT_ALLOW_STABLE_GITOPS_SOURCE` | unset | Must be `true` to accept the stable `platforminit-platform` repository as the source |

### Reachability rule (Argo CD fetches from GitHub, never from this workspace)

- The selected revision must already be pushed to the remote repository. Whenever the committed default is overridden, [`bootstrap-argocd.sh`](../platform/cluster/addons/argocd/bootstrap-argocd.sh:1) probes it with `git ls-remote` **before the first cluster mutation** and aborts with an actionable error when the revision is not reachable remotely. A branch that only exists in the local working tree (for example a controller-submitted change that was never pushed) is never reconciliation evidence.
- Credentials are never embedded in `PLATFORMINIT_GITOPS_REPO_URL`; the bootstrap refuses a URL that carries userinfo, because an embedded token leaks into logs and rendered manifests.
- A private repository additionally needs an Argo CD repository registration and git credentials for the CLI on the bootstrap host. Register it without writing the token to a file, to shell history or to Git:

```bash
# 1. Register the repository credential with Argo CD. The secret is typed at the
#    prompt, never echoed, never committed and removed from the environment again.
read -rsp "GitOps repository token: " PLATFORMINIT_GITOPS_REPO_TOKEN; echo
kubectl -n argocd create secret generic platforminit-gitops-repo \
  --from-literal=type=git \
  --from-literal=url="$PLATFORMINIT_GITOPS_REPO_URL" \
  --from-literal=username="${PLATFORMINIT_GITOPS_REPO_USERNAME:-git}" \
  --from-literal=password="${PLATFORMINIT_GITOPS_REPO_TOKEN}" \
  --dry-run=client -o yaml | kubectl apply -f -
kubectl -n argocd label secret platforminit-gitops-repo \
  argocd.argoproj.io/secret-type=repository --overwrite >/dev/null
unset PLATFORMINIT_GITOPS_REPO_TOKEN

# 2. Give the bootstrap host's git CLI the same access (for example a git
#    credential helper) so the reachability probe can read the repository.
#    Never place the token in the repository URL.
```

Rules enforced by [`ch04-validate-platform-services-gitops-contract.sh`](../platform/cluster/validate/ch04-validate-platform-services-gitops-contract.sh:1):

- The `platform-services` AppProject must not declare wildcard group/kind permissions, must explicitly
  allow every kind present in a synced directory, and must limit destinations to the namespaces the
  generated Applications actually use.
- Both bootstrap scripts must validate the version tag syntax, must keep a committed version/SHA-256
  pin, must verify the downloaded manifest before the first `kubectl apply`, and must not accept a
  manifest URL override.
- `application-argocd-self.yaml` and `applicationset-platform-services.yaml` must declare identical `repoURL`/`targetRevision`, inside the documented roo-lab boundary.
- `bootstrap-argocd.sh` defaults (`GITOPS_COMMITTED_REPO_URL`, `GITOPS_COMMITTED_TARGET_REVISION`) must match those committed values, so the rendered and the committed source can never diverge silently.
- No `repoURL` may point at the stable `platforminit-platform` repository in this repository, and the bootstrap refuses it unless `PLATFORMINIT_ALLOW_STABLE_GITOPS_SOURCE=true` is set explicitly.
- `AppProject.spec.sourceRepos` must allow the committed source.
- The bootstrap must prove the selected revision exists in the remote repository (`git ls-remote`) and must refuse a repository URL that embeds credentials.
- `bootstrap-argocd.sh` must type/range-validate `ARGOCD_SYNC_TIMEOUT` (default 300s, validated range 30-1800s) before the first arithmetic use and the first cluster call: the wait helpers evaluate it in `$((SECONDS + ARGOCD_SYNC_TIMEOUT))`, where Bash recursively evaluates array subscripts and command substitutions, and a nonnumeric value would abort only after Argo CD had been mutated.
- This document must keep stating the pushed/reachable prerequisite and the secret-safe repository registration, and must not advertise a rehearsal revision that is never pushed.

**Promotion step (required before bootstrap):** the committed default is the lab repository at `dev`. The revision referenced by `argocd-self` must contain `platform/cluster/manifests/argocd`, therefore the batch branch has to be pushed and merged into `dev` (and later promoted into `platforminit-platform`) before a default bootstrap. The self-managed Application, the AppProject it creates and the ApplicationSet it generates then all resolve from one pushed revision that actually contains these files.

**Pre-promotion rehearsal (optional, requires a pushed revision):** Argo CD fetches its source from the remote repository, so the rehearsal revision must be pushed first — an unpushed local branch, or a delivery that was never pushed by the controller, cannot be rehearsed:

```bash
# 1. Push the revision Argo CD is expected to fetch.
git push origin batch/platform-ch04-platform-services-gitops-contract

# 2. Bootstrap against that pushed revision; the script probes it with
#    git ls-remote before touching the cluster and aborts if it is missing.
sudo PLATFORMINIT_ALLOW_LIVE_ARGOCD_BOOTSTRAP=true \
  PLATFORMINIT_GITOPS_REPO_URL="https://github.com/platforminit/platforminit-roo-lab.git" \
  PLATFORMINIT_GITOPS_TARGET_REVISION="batch/platform-ch04-platform-services-gitops-contract" \
  bash platform/cluster/addons/argocd/bootstrap-argocd.sh
```

In this mode the Argo CD manifests are rendered with the requested source, the rendered AppProject and ApplicationSet are registered once (the single documented bootstrap exception), and automated self-management sync is disabled for the session so bootstrap does not fight the committed default. Re-run without the overrides once the change is promoted to `dev` to restore automated self-management.

## GitOps topology

```
argocd-self (Application, project: default, platform/cluster/manifests/argocd)
  |- AppProject        platform-services
  |- ApplicationSet    platform-services
       |- Application  platform-traefik-exposure        -> platform/cluster/manifests/traefik
       |- Application  platform-cert-manager-issuers    -> platform/cluster/addons/cert-manager
```

- `argocd-self` uses `prune: false`: an Application that owns its own AppProject/ApplicationSet must not be able to prune its own control path.
- The ApplicationSet uses a list generator, `goTemplate: true` with `missingkey=error`, and the same pinned `repoURL`/`targetRevision` as `argocd-self`.
- Generated Applications use automated sync with `selfHeal: true`, `prune: true`, `ApplyOutOfSyncOnly=true`, `PruneLast=true` and `CreateNamespace=true`.
- `directory.recurse` is `false`, so only the manifests directly in each synced directory are applied. Smoke-test manifests (for example [`smoke/demo-cert-smoke.yaml`](../platform/cluster/addons/cert-manager/smoke/demo-cert-smoke.yaml:1)) are therefore never synced.
- The AppProject allows only the two PlatformInit repositories and the `kube-system` and `cert-manager`
  destinations that the generated Applications actually target.

## Least-privilege AppProject (no wildcard permissions)

The `platform-services` AppProject is where Argo CD decides what a repository commit may create, so its
resource permissions are an explicit allowlist instead of wildcard `*` group/kind entries. Every entry
is demonstrated by exactly one manifest in a directory the ApplicationSet syncs:

| Scope | Entry | Demonstrated by |
|---|---|---|
| Cluster | `cert-manager.io/ClusterIssuer` | [`clusterissuer-letsencrypt-cloudflare.yaml`](../platform/cluster/addons/cert-manager/clusterissuer-letsencrypt-cloudflare.yaml:1) |
| Namespaced (`kube-system`) | `helm.cattle.io/HelmChartConfig` | [`traefik-helmchartconfig.yaml`](../platform/cluster/manifests/traefik/traefik-helmchartconfig.yaml:1) |

- `HelmChartConfig` is a **namespaced** k3s kind (the manifest declares `metadata.namespace: kube-system`),
  so it belongs in `namespaceResourceWhitelist`; only the `ClusterIssuer` is cluster-scoped.
- The list deliberately excludes RBAC escalation primitives (`ClusterRole`, `ClusterRoleBinding`,
  `Role`, `RoleBinding`, `ServiceAccount`, ...), CRDs, admission webhooks and arbitrary workloads.
  Argo CD rejects a synced object that the project does not match, so repository write access can no
  longer be converted into cluster-admin deployment authority.
- Destinations are limited to the namespaces the generated Applications target (`kube-system`,
  `cert-manager`). Adding a kind or a destination is a deliberate, reviewable change: extend the
  manifest **and** [`ch04-validate-platform-services-gitops-contract.sh`](../platform/cluster/validate/ch04-validate-platform-services-gitops-contract.sh:1)
  in the same commit, because that validator fails on a wildcard, on a synced kind that is missing from
  the allowlist, and on an unexpected destination.
- **Accepted residual risk:** a `HelmChartConfig` in `kube-system` is the supported k3s mechanism for the
  Traefik exposure required by the CH04 acceptance criteria, and the k3s helm controller applies the chart
  it names cluster-wide. That is the only cluster-wide effect this project still owns.

## Exposure and TLS contract

- Traefik Service is `type: LoadBalancer` exposing ports 80 and 443; HTTP redirects to HTTPS at the entrypoint level.
- The LoadBalancer must report a bound endpoint (`status.loadBalancer.ingress[].ip` **or** `.hostname`). A Service stuck in `pending` fails validation after `LB_WAIT_TIMEOUT` (default 60s, validated range 15-900s; the value is range-checked before the first cluster call) instead of producing a warning-only success.
- cert-manager DNS-01 uses the `cloudflare-api-token-secret` secret (key `api-token`) in the `cert-manager` namespace.
- Issuers: `letsencrypt-staging` (smoke tests) and `letsencrypt-prod`.
- Certificate secrets stay in the namespace of the requesting workload; no cross-namespace TLS secret reuse.
- The Cloudflare API token is operator-provided (`CF_API_TOKEN`), never committed, and never echoed by tooling.

### Staging issuance evidence (opt-in, mutating)

The default cert-manager validator is read-only and only proves that the CRDs, issuers, solver wiring and token secret exist. Issuance itself is proven by the bounded smoke check:

```bash
sudo PLATFORMINIT_ALLOW_STAGING_CERT_SMOKE=true \
  bash platform/cluster/validate/ch04-smoke-staging-certificate.sh
```

- Guarded: refuses to run without `PLATFORMINIT_ALLOW_STAGING_CERT_SMOKE=true`.
- Staging only: refuses any issuer other than `letsencrypt-staging`; the production issuer is never used.
- Run-owned: every invocation derives a unique run id (`SMOKE_RUN_ID`, default UTC timestamp + PID) and names the namespace (`SMOKE_NAMESPACE_PREFIX`, default `cert-manager-smoke`), the Certificate, the target TLS Secret and a `platforminit.io/smoke-run` label from it. A pre-existing object for the same run id is refused, never adopted, overwritten or deleted, so an operator typo cannot reach operator-owned resources.
- Bounded: `SMOKE_TIMEOUT` (default 300s, validated range 30-1800s) bounds the `Ready=True` wait. The value is range-checked before the first cluster call, so a smoke run can neither skip issuance nor hold an operator session indefinitely.
- Self-cleaning: the Certificate, the issued TLS Secret and the run-owned namespace are removed on exit, on success and on failure. There is no keep-resources bypass that could strand resources; cleanup only ever touches objects carrying this run's identity.
- Diagnostic-safe: on failure it prints Certificate conditions plus `Order`/`Challenge` state and reason fields only — never Secret data, tokens or raw resource dumps.

**Evidence boundary:** a `PASS=0 FAIL=0`-class read-only run does not demonstrate issuance. Treat the smoke check output (Certificate `Ready=True` plus the issued Secret name) as the issuance evidence, and record the exact command and revision it ran against.

## Validation

| Validator | Scope |
|---|---|
| [`ch04-validate-platform-services-gitops-contract.sh`](../platform/cluster/validate/ch04-validate-platform-services-gitops-contract.sh:1) | Repository-only contract check; no cluster access required; enforces fresh-cluster bootstrap ordering, GitOps source inputs, LoadBalancer-endpoint strictness, the smoke guard and secret hygiene |
| [`ch04-validate-traefik-exposure.sh`](../platform/cluster/validate/ch04-validate-traefik-exposure.sh:1) | Live cluster: LoadBalancer type, ports 80/443, ServiceLB, bound IP **or** hostname, IngressClass |
| [`ch04-validate-cert-manager-dns01.sh`](../platform/cluster/validate/ch04-validate-cert-manager-dns01.sh:1) | Live cluster, read-only: CRDs, control plane, issuers, Cloudflare solver, token secret |
| [`ch04-smoke-staging-certificate.sh`](../platform/cluster/validate/ch04-smoke-staging-certificate.sh:1) | Live cluster, opt-in and mutating: bounded staging Certificate issuance with unique run-owned resources and unconditional cleanup |
| [`ch04-validate-argocd-bootstrap.sh`](../platform/cluster/validate/ch04-validate-argocd-bootstrap.sh:1) | Live cluster: control plane, ingress mode, AppProject, ApplicationSet, `argocd-self` Synced, generated Applications |

All validators except the opt-in smoke check are read-only, aggregate every finding in one run, and exit non-zero when any check fails.

## Rollback and break-glass

1. Delete the generated Applications (`kubectl -n argocd delete application platform-traefik-exposure platform-cert-manager-issuers`) to stop reconciling a service.
2. Suspend the ApplicationSet (`kubectl -n argocd patch applicationset platform-services --type merge -p '{"spec":{"template":{"spec":{"syncPolicy":null}}}}'`) before making emergency manual changes.
3. Do not delete `argocd-self` while the AppProject/ApplicationSet are still needed: they would be garbage-collected with it. Re-apply [`application-argocd-self.yaml`](../platform/cluster/manifests/argocd/application-argocd-self.yaml:1) to restore ownership.
4. Full host recovery remains CH01/CH02: the host is disposable and the recovery path is the stable `platforminit-platform` repository (see [`docs/roo-lab/RECOVERY_CHAIN.md`](roo-lab/RECOVERY_CHAIN.md:1)).

## Non-goals

- No identity/SSO (CH04.5, CH04.6) and no observability stack (CH05) ownership.
- No production/customer environment changes; dev host only.
- No secret material in Git, ever.
