## Resolved command-injection finding

1. **Severity:** resolved Medium.
   - **File/symbol:** [`ARGOCD_SYNC_TIMEOUT`](../../platform/cluster/addons/argocd/bootstrap-argocd.sh:56), consumed by [`wait_for_application_synced()`](../../platform/cluster/addons/argocd/bootstrap-argocd.sh:229) and [`wait_for_object()`](../../platform/cluster/addons/argocd/bootstrap-argocd.sh:244).
   - **Prior impact:** inherited text reached Bash arithmetic in a root-run bootstrap. Bash can recursively evaluate array subscripts and command substitutions in arithmetic expressions, permitting command execution before the fix; ordinary malformed input could also fail only after cluster mutation.
   - **Current control:** [`bootstrap-argocd.sh`](../../platform/cluster/addons/argocd/bootstrap-argocd.sh:112) accepts only one to nine decimal digits, normalizes with `10#` at [`bootstrap-argocd.sh`](../../platform/cluster/addons/argocd/bootstrap-argocd.sh:116), and enforces 30-1800 seconds at [`bootstrap-argocd.sh`](../../platform/cluster/addons/argocd/bootstrap-argocd.sh:117). These checks execute before root/tool preflight, the first wait arithmetic, and the first cluster access. Only the normalized value reaches arithmetic.
   - **Failure scenario retest:** `ARGOCD_SYNC_TIMEOUT='x[$(touch /tmp/platforminit-owasp-timeout-probe)]'` exited at the digit guard; the marker remained absent. Values 29 and 1801 failed at the range guard. Values 30, 0300, 300, and 1800 passed timeout validation and then stopped at the non-root preflight gate, confirming explicit decimal normalization and inclusive bounds without cluster access.
   - **Regression control:** [`ch04-validate-platform-services-gitops-contract.sh`](../../platform/cluster/validate/ch04-validate-platform-services-gitops-contract.sh:690) asserts constants, base-10 normalization, digit-only malformed-input rejection, and ordering before the first actual deadline expression and cluster call. The embedded payload is compared as a quoted string and is never sourced or evaluated.

## Security boundary review

- **Secret exposure/privacy:** no plaintext API token/password pattern was found in changed manifests or scripts. [`install-cert-manager.sh`](../../platform/cluster/addons/cert-manager/install-cert-manager.sh:133) accepts `CF_API_TOKEN` only from the environment, passes it through a quoted `kubectl create secret --from-literal` argument, suppresses generated Secret YAML output, and logs only the Secret name. Documentation uses environment references rather than literal credentials.
- **Command/input injection:** GitOps repository/revision inputs remain syntax-checked and repository URLs are constrained to fixed PlatformInit allowlists; embedded credentials are rejected. The newly reported arithmetic path is closed. No `eval` or dynamic shell command construction was introduced.
- **Destructive behavior:** cleanup remains restricted to generated `/tmp` directories in the bootstrap and uniquely named, run-owned smoke resources. No broadened deletion or cloud/infrastructure action was introduced.
- **Privilege boundary:** the live installers remain explicit root-run paths with acknowledgment guards. Timeout validation now precedes privileged operation and cluster access, reducing partial-mutation and root command-execution risk. No sudo grant or privilege escalation was added.
- **Argo CD authorization:** [`appproject-platform-services.yaml`](../../platform/cluster/manifests/argocd/appproject-platform-services.yaml:18) allows only the two fixed PlatformInit repositories; destinations are limited to `kube-system` and `cert-manager`; resource kinds are limited to `cert-manager.io/ClusterIssuer` and `helm.cattle.io/HelmChartConfig`. No wildcard, RBAC primitive, arbitrary workload, CRD, or webhook permission is present.
- **Supply chain/TLS:** [`bootstrap-argocd.sh`](../../platform/cluster/addons/argocd/bootstrap-argocd.sh:67) and [`install-cert-manager.sh`](../../platform/cluster/addons/cert-manager/install-cert-manager.sh:38) retain committed release digests, fixed HTTPS origins, strict version/URL syntax, TLS-only downloads, and verification before local-file apply. No remote URL is sent directly to `kubectl apply` and no mutable installer source was introduced.
- **Identity/header trust:** the changed CH04 scope does not alter Authentik, OIDC, forwardAuth, or trusted-header behavior.
- **GitHub Actions permissions/environment boundaries:** no workflow or production/customer environment file is changed. The stable GitOps repository remains behind explicit acknowledgment. No infrastructure workflow or cluster/cloud mutation was run during review.
- **Evidence leakage:** repository validators report names/status only and do not dump Secret data or raw credentials. Review probes used synthetic payloads and left no marker artifact.
- **Controller integrity:** task status and generated task views were advanced through `taskctl`; no competing task source of truth was introduced. Product changes remain within the controller allowlist.
